<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Screen component -> dispatchMove | Screens (Plan 01-05/01-06) call `dispatchMove` with a `Move` object; `GameProvider` is the last stop before `applyMove` — no additional validation happens here, all rule enforcement is `applyMove`'s job (already covered in Plan 01-02/01-03's threat register). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-07 | Information Disclosure | Toast rendering `result.error.message` | accept | Error messages are static, developer-authored strings (never interpolate untrusted move payload contents into a toast message) — no injection surface since React escapes text content by default and no `dangerouslySetInnerHTML` is used. |
| T-01-08 | Denial of Service | `useToast`'s dismiss timer | accept | A malicious/buggy caller spamming `showToast` just keeps resetting a 3.5s timer (D-07's intended behavior) — worst case is a toast that never dismisses while calls continue, not a crash or resource leak (single `setTimeout` ref, always cleared before replacement). |
</threat_model>
