## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser optimistic state → displayed board | Local prediction is presentational only until confirmed |
| browser → `apply-move` HTTP | The client's local validation is an affordance, not a control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-32 | Tampering | Optimistic state diverging permanently from the server | mitigate | `applyServerRoom` unconditionally snaps to any newer-version server state; the optimistic value is never treated as authoritative and is never written anywhere |
| T-02-33 | Elevation of Privilege | Bypassing the client-side legal-move check | accept | Expected and irrelevant: the client check exists only to make races rare and feedback instant. `apply-move` re-validates every move through the same engine (plan 02-06), so bypassing the client gains nothing |
| T-02-34 | Repudiation | A player disputing a reversed move | mitigate | The reconciliation toast names what happened, and plan 02-03's `moves` audit table records the authoritative sequence with versions |
</threat_model>
