<objective>
Implement MPLAY-07's server-authority half: a room's turn auto-pickup timeout (`TURN_GRACE_MS`,
hardcoded at 60000ms today) becomes a per-room, host-configurable value stored on `GameState` and
enforced server-side, exactly as settled in this session's Socratic exploration - controller is
`state.host` (the same permission concept `LobbyScreen.tsx` already uses for Start Game/kicking
players), only configurable while `state.phase === 'lobby'`, bounded to `[30000, 300000]`ms
inclusive, defaulting to `60000`ms so any room that never touches this setting behaves identically
to today.

This plan does **not** touch the lobby UI. It builds the new `SET_TURN_TIMEOUT` move type through
the existing `dispatchMove -> submitMove -> apply-move Edge Function -> withVersionRetry` pipeline
(confirmed as the closest architectural precedent by reading `READY_UP`'s end-to-end wiring: engine
handler in `applyMove.ts`, `VALID_MOVE_TYPES` in `applyRoomMove.ts`, no separate one-off Edge
Function), makes `checkTurnTimeout` read the configured value instead of the hardcoded constant,
and seeds new rooms with the 60s default. A player can only reach this new move type today by
dispatching it programmatically (proven by this plan's own tests) - nobody can reach it through the
UI yet. **`MPLAY-07` is not fully closed by this plan alone**: "adjustable in the lobby" and
"visible to all players, not just the host" are UI-facing halves of the requirement that a follow-up
plan (`02-19`, not yet written) must deliver by wiring `LobbyScreen.tsx` to dispatch this move and
by making `useTurnTimeoutSweep.ts`/`GameScreen.tsx` read the configured value instead of the
still-hardcoded `TURN_GRACE_MS` they use today. See this plan's closing report for that scope
boundary.

Adding `turnTimeoutMs: number` as a required `GameState` field (matching every other field's
required, non-optional convention in that interface) ripples into every literal `GameState` object
built outside the shared `buildGameState` test helper, because `tsconfig.app.json` includes all of
`src` and `supabase/functions/_shared` under `tsc -b`'s strict project build - `npm run build` type-
checks every test file too, not just production code. Task 1 below fixes every such site in the same
task that introduces the field, so the repo compiles cleanly at every intermediate commit, not just
at the end of the plan.

Purpose: closes the gap between D-05's originally-hardcoded 60s grace period and this session's
explicit user decision that a table should be able to tune how long they wait before an idle
opponent's cards get auto-picked-up, without touching the two independent liveness constants
(`HEARTBEAT_INTERVAL_MS`, `DISCONNECT_THRESHOLD_MS`) that stay fixed.

Output: a `SET_TURN_TIMEOUT` move enforced by the same `applyMove` reducer every other move goes
through (MPLAY-04), a `GameState.turnTimeoutMs` field flowing through the existing Realtime
broadcast with no new schema/migration, and `checkTurnTimeout` honouring it with a documented,
tested fallback for any room whose stored state predates this plan.
</objective>
