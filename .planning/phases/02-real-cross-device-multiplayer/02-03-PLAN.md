`rooms` table, columns exactly matching `RoomRow` in `src/supabase/roomTypes.ts`:

  - `state jsonb not null` — the whole `GameState`, stored unnormalised so `applyMove`'s
    input/output shape needs zero adaptation
  - `version bigint not null default 0` — optimistic-concurrency token
  - `turn_started_at timestamptz not null default now()` — D-05's server-verified turn clock

    written only with the server's `now()`, never a client-supplied time. This is the
    server-verified "who is disconnected" signal that D-06 (rejoin-by-name matching a
    disconnected seat), D-07 (host removes an AFK player) and D-08 (host auto-transfer) need;
    Realtime Presence is ephemeral and client-reported and must not be used for those.
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`

Deliberately do NOT add a `host_player_id` column. `state->>'host'` is the single source of
truth for host identity because `GameState.host` already exists and `LobbyScreen.tsx` renders
from it; a mirrored column would be a second, drift-prone truth. This is a considered
deviation from RESEARCH.md's proposed schema.

`moves` append-only audit table per RESEARCH.md's Code Examples: `id bigint generated always
as identity primary key`, `room_code text not null references rooms(room_code) on delete
cascade`, `player_id uuid not null`, `move jsonb not null`, `resulting_version bigint not
null`, `created_at timestamptz not null default now()`. This exists to make D-11/D-12
reconciliation incidents debuggable after the fact.

Realtime: `alter publication supabase_realtime add table rooms;`. Do not add `moves` to the
publication — clients never subscribe to the audit log. Do not set `replica identity full`;
this phase's subscription reads only `new.state`/`new.version`/`new.turn_started_at`
(RESEARCH.md Pitfall 7).

RLS — this is the MPLAY-04 enforcement mechanism, so get it exactly right:
  - `alter table rooms enable row level security;` and the same for `moves`
  - `create policy` granting `select` `to authenticated` `using (true)` on both tables. Per
    RESEARCH.md Open Question 2 and Assumption A4 this deliberately preserves the existing
    trust posture, where the 36^6 room code is the access boundary — it is not a new gap
    relative to the localStorage design being replaced.
  - Create NO insert, update or delete policy for `authenticated` on either table. The
    service-role client used inside Edge Functions bypasses RLS and is the only writer.
    Add a SQL comment saying so explicitly, so a future reader does not "fix" the missing
    write policies.
  - `revoke insert, update, delete on rooms, moves from anon, authenticated;` as belt-and-braces
    alongside the absent policies.

Add an index supporting D-05's lazy timeout sweep: a partial index on `turn_started_at` where
`state->>'phase' = 'playing'`.

  <behavior>
    - `withVersionRetry` calls the supplied `read` then `compute` then `write`, and returns the write result when the write reports 1 affected row
    - When `write` reports 0 affected rows (a concurrent update raced), `withVersionRetry` re-reads and recomputes, up to 3 attempts total
    - After 3 failed attempts `withVersionRetry` resolves to an `EdgeError` with code `CONFLICT`
    - When `compute` returns an `EdgeError`, `withVersionRetry` returns it immediately without writing and without retrying
    - When `read` returns null, `withVersionRetry` returns an `EdgeError` with code `ROOM_NOT_FOUND`
    - `jsonResponse` serialises `{ room }` with status 200 and `{ error }` with the status mapped from the edge error code (400 for `BAD_REQUEST`/validation codes, 401 for `UNAUTHENTICATED`, 403 for `NOT_HOST`/`NOT_IN_ROOM`, 404 for `ROOM_NOT_FOUND`, 409 for `CONFLICT`)
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → PostgREST → `rooms`/`moves` | Any browser holding an anon JWT can attempt direct table writes |
| Edge Function service-role client → Postgres | Full RLS bypass; the only sanctioned write path |
| concurrent writers → same room row | Two writes derived from the same base state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering / Elevation of Privilege | `rooms` and `moves` tables via PostgREST | mitigate | RLS enabled with a `select`-only policy and zero insert/update/delete policies for `authenticated`, plus an explicit `revoke insert, update, delete ... from anon, authenticated` (Task 1). This, not the Edge Function's existence, is what makes MPLAY-04 enforceable |
| T-02-07 | Tampering | Lost update from a concurrent write | mitigate | `version` column plus `withVersionRetry`'s conditional update and bounded re-read/recompute (Task 2); a stale replayed request naturally no-ops because its expected version no longer matches |
| T-02-08 | Information Disclosure | `select ... using (true)` on `rooms` | accept | Preserves the exact posture of the localStorage design being replaced — the 36^6 room code is the access boundary and room state contains only card positions in a party game (RESEARCH.md Open Question 2, Assumption A4). Revisit if anything more sensitive is ever stored on a room |
| T-02-09 | Repudiation | Disputed/reconciled moves | mitigate | Append-only `moves` audit table records player, move payload and resulting version for every applied move (Task 1) |
</threat_model>
