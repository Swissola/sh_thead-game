<objective>
Close the blocker gap from `02-UAT.md` test 4b: a turn that times out while the discard pile is
empty currently stalls the table permanently and silently. `applyPickUpPile` rejects with
`PILE_EMPTY`, `checkTurnTimeout` forwards that error unwritten, nothing about the room changes
between sweeps, and `useTurnTimeoutSweep` swallows every sweep error - so the identical failure
repeats every 5 seconds forever with zero user-visible signal.

Purpose: D-05 exists precisely to stop a stuck table ("keeps the game moving without them").
An empty pile is an edge case D-05's original design did not cover, which reintroduces the
exact failure mode D-05 was written to prevent. MPLAY-06's correctness half is not delivered
while this hole is open. MPLAY-04 applies because the fallback move must go through the same
server-side `applyMove` boundary as every other move.
Output: a rank-aware auto-play fallback inside `checkTurnTimeout`, plus a sweep hook that no
longer discards unexpected failures without trace.
</objective>

  <action>
Add an exported pure helper to `supabase/functions/_shared/turnTimeout.ts`:

`selectAutoPlayMove(state: GameState, player: Player): Move | null`

It resolves `GameLogic.getAvailableCardSource(player)` and returns a `PLAY_CARDS` move whose
`cards` array holds exactly one `CardSelection` of `{ type: <that source>, index: <chosen> }`,
with `playerId` set to `player.id`. Return `null` when the resolved source holds no non-null
card, which is the only case the caller cannot resolve.

Selection rules, in order:
  - Source `faceDown`: choose the lowest index whose slot is non-null. Do **not** read
    `card.rank` on that branch at all. Face-down cards are blind by game design (CLAUDE.md:
    "Face-down cards must never expose rank/suit to the UI before the player commits"), so
    there is no rank to compare and index 0 is the deterministic choice the user specified on
    2026-07-28. Playing it blind is safe: `applyPlayCards`'s `isBlindPlay` branch turns an
    unplayable blind card into a legal pick-up-your-own-card outcome rather than an error, so
    the turn resolves either way.
  - Source `hand` or `faceUp` with `state.isFirstTurn` true: compute
    `GameLogic.getStartingCard(player)` and restrict the candidate set to cards of that rank
    before comparing. Without this the fallback picks a `2` or `3` on the opening turn and
    `applyPlayCards` rejects it with `FIRST_TURN_INVALID`, reproducing the very stall this plan
    closes. When `getStartingCard` returns `null` the player genuinely has no legal opening
    move under existing rules - fall through to the plain lowest-card selection and let the
    engine's own error surface rather than inventing a rule here.
  - Otherwise: minimum `GameLogic.RANK_VALUES[card.rank]` across the non-null entries, ties
    broken by the lower array index. Use `RANK_VALUES` as the comparator exactly as
    `sortHand`'s rank mode already does - do not re-derive an ordering, and note Ace is 14 and
    2 is 2, so "lowest" here means lowest `RANK_VALUES`, which is what the user specified.

Then extend `checkTurnTimeout`'s existing `if (result.error)` branch. Today it forwards every
engine rejection unwritten. Change it to: forward unchanged for any code other than
`ERROR_CODES.PILE_EMPTY`; on `PILE_EMPTY`, call `selectAutoPlayMove(row.state, timedOutPlayer)`,
forward the original `PILE_EMPTY` error unwritten if it returns `null`, otherwise apply the
returned move through the same `applyMove` from `./engine.ts` and return its state with
`turnStartedAt: store.now()`.

If the second `applyMove` call also errors, forward that error unwritten exactly like the
original `PICK_UP_PILE` rejection - same `{ code, message }` forwarding, no write, no second
fallback attempt. The selection rules above are designed so this branch is near-unreachable
(any single card is legal on an empty pile, the source-order gate is satisfied by construction,
and the `isFirstTurn` restriction covers the one remaining engine gate), but the only case that
can still reach it - `getStartingCard` returning `null` on an opening turn - is a pre-existing
engine-level "this player has no legal opening move" condition, not something this plan invents
a new rule to paper over. Forwarding keeps the failure visible rather than silently swallowed.

Never hand-roll the play. `applyMove` is the server's trust boundary (MPLAY-04) and the same
discipline the existing `PICK_UP_PILE` path already follows; a bespoke card-removal here would
be a second, drift-prone copy of the rules. Import `ERROR_CODES` from `./engine.ts`, which
already re-exports it - the engine and edge code sets stay deliberately disjoint
(`roomTypes.ts` docstring), so compare against `ERROR_CODES.PILE_EMPTY`, not a string literal.
