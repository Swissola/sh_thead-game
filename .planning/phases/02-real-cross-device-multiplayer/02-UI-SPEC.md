# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** Phase 2 is backend/networking-first (Supabase Postgres/Realtime/Edge Functions/anon-auth). Per `02-CONTEXT.md`'s domain note, the UI surface is deliberately small and incidental — five additions to the existing screens, not a new screen or a design-system pass. This contract locks down exactly those five additions and inherits everything else (typography scale, page chrome, existing buttons/toasts) from the app as it stands after Phase 1. Broader visual/responsive work is Phase 3/5/6's job.

The five in-scope elements (traced to CONTEXT.md decisions):

1. Offline / auto-picking-up badge on a disconnected opponent's player-tile, clearing via a reconnect toast (D-10)
2. A visually distinct move-reconciliation toast style, separate from the existing invalid-move toast (D-11, D-12)
3. A "Leave Game" button, available at all times during a game (D-14)
4. A copy-to-clipboard room code button (already exists) plus a new copy-join-link button, and the join-link's pre-fill entry point (D-15)
5. Last-used display name pre-filled (not re-styled) on the Menu screen (D-09)

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled components styled directly with Tailwind utility classes |
| Icon library | `lucide-react` (already the sole icon dependency; used throughout `MenuScreen.tsx`, `LobbyScreen.tsx`, `GameScreen.tsx`, `Toast.tsx`) |
| Font | none declared — Tailwind's default system sans stack (no `font-family` override anywhere in `index.css`/`App.css`) |

**shadcn gate note:** `components.json` is not present and no shadcn preset exists anywhere in the repo. The gate was considered and deliberately **not** triggered for this phase: the app already has a complete, consistent bespoke Tailwind visual language (dark slate/purple palette, pink→purple gradients, `lucide-react` icons) that predates any component-library decision, and CONTEXT.md explicitly delegates this phase's styling to "the existing Toast/UI patterns," not a new system. Introducing shadcn now, for five incidental elements, would itself be the kind of broader design-system pass the scope note rules out. Revisit at Phase 3 (Responsive UI, `UI hint: yes`), which is the natural point to reconsider a component library against a real layout overhaul.

## Spacing Scale

Declared values (must be multiples of 4) — this is the scale the existing codebase already uses (Tailwind's default spacing, confirmed via `MenuScreen.tsx`/`LobbyScreen.tsx`/`GameScreen.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`) |
| sm | 8px | Compact padding (`p-2`, `gap-2`), badge vertical padding (`py-1`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`, `mb-4`) |
| lg | 24px | Section padding (`p-6`, `mb-6`) |
| xl | 32px | Layout gaps (`mb-8`) |
| 2xl | 48px | Major section breaks (not used by this phase's new elements) |
| 3xl | 64px | Page-level spacing (not used by this phase's new elements) |

Exceptions: the project already uses `p-3`/`gap-3`/`py-3` (12px) throughout existing buttons and inputs — this predates Phase 2 and is not a deviation introduced by this contract. New elements in this phase reuse the **existing 8px badge pattern exactly** (`text-xs px-2 py-1 rounded`, as already used for the Lobby's "You" badge) rather than inventing a new badge shape.

## Typography

Inherited from the existing app (unchanged); this phase's new elements (badges, toast copy, button labels) map onto the existing Body/Label rows only — Heading/Display are listed for completeness and are **not** touched by this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Label | 12px (`text-xs`) | 600 semibold | 1.2 |
| Heading | 20px (`text-xl`) | 700 bold | 1.2 |
| Display | 48px (`text-5xl`) | 900 black | 1.1 |

Applied to this phase's elements:
- Offline / auto-picking-up badges, "reconnected"/reconciliation toast pill labels → **Label** (12px/600)
- Toast body copy (reconciliation message, reconnect message) → **Body** (14px/400), matching the existing `Toast.tsx` `text-sm` message style exactly
- "Leave Game" button label → same weight/size as existing header buttons (`font-bold`, inherits button convention below, not a new type role)

## Color

Inherited 60/30/10 split (unchanged from the existing app; documented here because the new elements must slot into it correctly):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slate-900` (#0f172a) via the existing `from-slate-900 via-purple-900 to-slate-900` page background gradient | Page background |
| Secondary (30%) | `slate-800` (#1e293b) / `slate-700` (#334155) | Panels, cards, player-tiles, inputs, modals |
| Accent (10%) | `purple-500`/`purple-600` (#a855f7 / #9333ea), plus the pink→purple gradient | Reserved for: primary CTA buttons (Create Room, Start Game, Ready to Play), panel/header borders, the Rules button, room-code text, the existing "You" badge |
| Destructive | `red-500`/`red-600` (#ef4444 / #dc2626) | Reserved for: Pick Up Pile button, "Pick Up Anyway" confirm button, the existing invalid-move/error toast border |

**New semantic colors this phase adds** (extensions, not replacements — each reserved for exactly the elements listed):

| Role | Value | Reserved for |
|------|-------|---------------|
| Neutral/offline | `slate-500`/`slate-600` (#64748b / #475569) | The "Offline" badge (D-10 state 1) and the greyed-out treatment of a disconnected opponent's player-tile (`opacity-60`, `border-slate-600` in place of the tile's normal border) |
| Reconciliation/attention (amber) | `amber-500`/`amber-600` (#f59e0b / #d97706) | The "Offline - auto-picking up" badge (D-10 state 2) **and** the reconciliation-toast border (D-12) — one semantic colour for "the system automatically changed something," deliberately distinct from red (error) and green (success) |
| Positive/reconnect (green) | `green-500` (#22c55e) | The reconnect toast border only (D-10 clear event) — matches the app's existing use of green for positive/connected states (Play button, Ready state, Test Mode) |

Leave Game button is intentionally **not** red: it is a neutral exit action (the seat persists per D-04, rejoin is always possible), not a destructive one, so painting it red would misleadingly imply data loss and collide with Pick Up Pile's existing red meaning ("give up your current hand position"). Use `slate-700`/`slate-600` (same neutral family as the header's existing icon buttons).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Leave Game" (button, GameScreen header, always visible during a game) — icon: `LogOut` |
| Offline badge (D-10 state 1) | "Offline" — icon: `WifiOff`, on the greyed player-tile |
| Offline badge (D-10 state 2, post grace-period) | "Offline - auto-picking up" — icon: `RotateCw`, amber pill, replaces state 1's badge in place |
| Reconnect toast (D-10 clear) | "{name} reconnected" (e.g. "Bob reconnected") — icon: `CheckCircle2`, green-bordered toast variant, auto-dismiss at the existing 3500ms `DISMISS_MS` |
| Reconciliation toast (D-11/D-12) | "Your move didn't stick - synced with the latest game state." — icon: `RotateCcw`, amber-bordered toast variant, same 3500ms auto-dismiss. One generic message covers both real trigger sources (multi-tab race, grace-period auto-pickup racing a live move) — CONTEXT.md's `<specifics>` explicitly frames this as a rare edge case, not one needing per-cause copy variants |
| Copy room code (existing, unchanged) | Icon-only button, `Copy` → `Check` (green-400) on success, reverts after 2s |
| Copy join link (new, D-15) | Icon-only button next to the existing copy-code button, same interaction shape: `Link2` → `Check` (green-400) on success, reverts after 2s. Add `aria-label="Copy join link"` (and backfill `aria-label="Copy room code"` on the existing button while touching this area, since neither currently has one) |
| Menu display name field (D-09) | No copy change — placeholder stays "Enter your name"; the field's initial `value` now reads from a persisted last-used name instead of defaulting to `''`, still fully editable |
| Empty state | Not applicable — Phase 2 introduces no new empty-data view. (The existing "Waiting for players..." / "Waiting for host to start the game..." copy in `LobbyScreen.tsx` is unchanged and out of scope.) |
| Error state (existing pattern, unchanged) | Short, direct, present-tense: "Room not found", "Game has already started", "Failed to join room - please retry." New reconciliation copy above follows the same register: plain statement of what happened, no jargon. |
| Destructive confirmation | "Leave Game": clicking the header button opens a lightweight confirm dialog reusing the existing `pickUpConfirmation` portal pattern (`bg-black/50` overlay, `slate-800` panel, `border-2 border-purple-500`). Title: "Leave game?" Body: "You can rejoin any time with the same room code - your seat will be waiting." Buttons: "Keep Playing" (`slate-700`/`slate-600`, same neutral dismiss-button styling used elsewhere in the confirm-dialog pattern) and "Leave Game" (`bg-red-600 hover:bg-red-700`, matching the existing "Pick Up Anyway" confirm-button treatment for a final destructive-style confirm action, even though the underlying action is reversible). Neither label is generic — both name the specific choice being made, per the copywriting BLOCK list on vague labels like "Cancel"/"Submit"/"OK". This dialog is distinct from the pre-existing `pickUpConfirmation` dialog (`GameScreen.tsx:671`), which keeps its own "Cancel" label unchanged and is out of scope for this gate |

## Interaction Notes (non-visual, included for executor clarity)

- Offline badge state transition is a straight replace-in-place on the same player-tile — no layout shift, no additional DOM element, just swapping badge text/icon/colour class and the tile's opacity/border classes when presence flips.
- Reconnect toast and reconciliation toast reuse the existing `useToast`/`Toast` plumbing (`src/hooks/useToast.ts`, `src/components/Toast.tsx`), extended with a `variant` field (`'error' | 'reconcile' | 'reconnect'`, defaulting to `'error'` so every existing `showToast(...)` call site keeps working unchanged) rather than a parallel toast system.
- "Leave Game" sits in `GameScreen.tsx`'s header row, next to the existing Rules (`HelpCircle`) button, same `p-2 rounded-lg` icon-button shape but in the neutral slate palette rather than purple.
- Join-link routing (D-15) has no new visual surface beyond the second copy button — the pre-fill behaviour on landing via `/join/:code` reuses `MenuScreen.tsx`'s existing room-code input, just pre-populated and (per Claude's Discretion in CONTEXT.md) the exact route scheme is a planning/implementation decision, not a visual one.
