<objective>
Move room creation and joining server-side. Today `MenuScreen.tsx` generates a code, checks
for collisions and writes the whole room straight to storage — all three become impossible
once RLS denies client writes, and all three are trust-boundary operations in their own right
(RESEARCH.md Pitfall 3: it is not just the four `Move` types that need a boundary).

Purpose: MPLAY-01 (join by code from another device), MPLAY-03 (identity comes from the
verified JWT), MPLAY-04 (the only write path is a service-role Edge Function). This plan also
implements the whole reconnect story: D-01 auto-rejoin by uid, D-02 manual rejoin, D-06's
exactly-one-disconnected-name-match rule, and D-04's never-free-a-seat guarantee.
Output: `create-room` and `join-room` Edge Functions plus their unit-tested logic modules.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted client → `create-room` / `join-room` HTTP | Body, headers and claimed identity are all attacker-controlled |
| Edge Function → `rooms` table | Service-role write, RLS bypassed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Spoofing | `playerId` in the request body | mitigate | Both wrappers set the player id from `ctx.userClaims.sub` and ignore any body-supplied id; `scripts/check-edge-wrappers.mjs` fails the build if that ever regresses |
| T-02-14 | Elevation of Privilege | Seat takeover via rejoin-by-name | mitigate | `resolveSeat` requires exactly one name match against a seat stale by the server clock; a live seat returns `NAME_IN_USE` and multiple stale matches return `NAME_AMBIGUOUS` (D-06). Staleness never uses a client-supplied timestamp |
| T-02-15 | Tampering | Simultaneous joins clobbering each other | mitigate | All mutation runs through `withVersionRetry`'s conditional update, replacing the read-modify-write race documented in `MenuScreen.tsx`'s WR-02 comment |
| T-02-16 | Input Validation | Malformed JSON body or empty name | mitigate | Body parsed inside try/catch and rejected with `BAD_REQUEST` before any logic runs; whitespace-only names rejected before any database write |
| T-02-17 | Information Disclosure | Room-code guessing | accept | 6 base36 characters from `crypto.getRandomValues` (~2.2bn combinations), unchanged from the posture Phase 1's WR-03 established |
</threat_model>
