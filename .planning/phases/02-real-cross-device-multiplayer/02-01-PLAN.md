  <action>
Create `src/supabase/roomTypes.ts` — the single shared contract imported by both the browser
code and (later) the Deno Edge Functions. It must depend only on `./../types.ts` and nothing
from `@supabase/supabase-js`, so Deno can import it without pulling the browser SDK. Export:

  - `RoomRow`: `room_code: string`, `state: GameState`, `version: number`,
    `turn_started_at: string`, `player_seen: Record<string, string>`,
    `created_at: string`, `updated_at: string`
  - `ServerRoom`: `roomCode`, `state`, `version`, `turnStartedAt`, `playerSeen`
  - `rowToServerRoom(row: RoomRow): ServerRoom`
  - `EDGE_ERROR_CODES` as an `as const` object with values:
    `UNAUTHENTICATED`, `ROOM_NOT_FOUND`, `ROOM_CODE_COLLISION`, `GAME_ALREADY_STARTED`,
    `NAME_AMBIGUOUS`, `NAME_IN_USE`, `NOT_IN_ROOM`, `NOT_HOST`, `NOT_ENOUGH_PLAYERS`,
    `CONFLICT`, `TIMEOUT_NOT_ELAPSED`, `BAD_REQUEST`
  - `type EdgeErrorCode` derived from it
  - `interface EdgeError { code: EdgeErrorCode; message: string }`
  - `interface EdgeResult { room?: ServerRoom; error?: EdgeError }`
  - Timing constants: `TURN_GRACE_MS = 60000` (D-05's grace period),
    `HEARTBEAT_INTERVAL_MS = 15000`, `DISCONNECT_THRESHOLD_MS = 45000`

These edge codes are deliberately a *separate* closed set from `src/engine/errors.ts`'s
`ERROR_CODES` (Phase 1 D-04) — engine codes describe illegal moves, edge codes describe
network/lifecycle failures. Do not add edge codes to `ERROR_CODES` or vice versa.

in a Vitest/jsdom run without env vars does not throw at import time. Also export
`resetSupabaseClientForTests()` clearing the memo. Read env from
`import.meta.env.VITE_SUPABASE_URL` and `import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY`.
