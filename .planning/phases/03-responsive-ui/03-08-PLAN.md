  <how-to-verify>
    Start the dev server with `npm run dev:auto` (fixed on 127.0.0.1:5173) and use in-game Test Mode where a second player is not handy — note that Test Mode is fully client-side and never reads or writes `localStorage`.

    **A. Phone-width layout, no overflow (RESP-01)**
    1. Open Chrome DevTools responsive mode at 375px width. A real phone on the LAN is better if one is to hand.
    2. Walk the whole game: menu → lobby → setup phase → several turns of play → a pick-up → the celebration modal.
    3. Confirm at each step that nothing overflows horizontally and no horizontal page scrollbar appears. The hand should scroll horizontally *within its own strip*, not push the page wide.
    4. Rotate to landscape (or set a landscape viewport) and confirm the same layout simply gets more horizontal room — there should be no separate landscape arrangement (D-12).

    **B. Touch targets on a real device (RESP-03)**
    5. On the same 375px view, tap every interactive control: the three hand-sort buttons, the Rules and Leave Game header buttons, Play, Pick Up Pile, Ready to Play, both confirmation dialogs' buttons, the celebration Dismiss button, and in the lobby the two copy buttons, the timeout select and the remove-player button.
    6. Confirm each is comfortably tappable without zooming and that you never hit the neighbouring control by mistake.
    7. Specifically check a same-rank group in the hand: at phone width the cards must not overlap, and tapping a card must select *that* card, never the one beside it (this is the D-11 / Pitfall 5 case).

    **C. Keyboard-only play (RESP-04)**
    8. Put the mouse down. Using only Tab, Shift+Tab, arrows, Enter, Space and Escape, complete a full turn: reach the hand, arrow to a card, select it, arrow to a second card of the same rank, select that too, then reach the Play button and play them.
    9. Confirm arrow keys move focus *without* changing what is selected, and that the cyan focus ring is clearly distinguishable from the yellow selected ring on a card that is both focused and selected.
    10. Reach the face-down pile by keyboard and confirm you cannot select two face-down cards at once — selecting a second must deselect the first.
    11. Open the celebration modal (finish a hand, or use Test Mode to drive a player out) and confirm Tab cycles only inside the dialog, Escape closes it, and focus lands back where it was before it opened.

    **D. Screen-reader announcement (RESP-05)**
    12. Turn on NVDA (Windows) or VoiceOver (macOS).
    13. Trigger at least three consecutive turn changes and confirm each one is announced audibly as "Your turn" or "&lt;Name&gt;'s turn". Three in a row matters — Pitfall 2's failure mode is that the first announcement works and later ones silently stop.
    14. Open the celebration modal and confirm the screen reader announces it as a dialog and reads its heading ("SH!THEAD!" or "SAFE!").
    15. Focus a face-down card and confirm the screen reader says only "Face-down card" — it must never speak the card's real rank or suit. This is the blind-play invariant and a failure here is a blocker, not a polish item.
