## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Elevation of Privilege | remove-player button sizing | mitigate | The size change is additive class text only. The `disabled={!offline}` gate, the `isHost && player.id !== gameState.host` render condition and the `aria-label` are all asserted unchanged by Task 1 tests 5 and 6, so a bigger tap target cannot become a bigger permission. The `remove-player` Edge Function's own host check (Phase 02-07) is unaffected regardless |
| T-03-11 | Tampering | auto-pickup timeout select sizing | mitigate | Only `py-1` → `py-2` plus `min-h-11` change; the `value`, `onChange` and `TURN_TIMEOUT_OPTIONS_MS` bounds are untouched, so `SET_TURN_TIMEOUT`'s `MIN_TURN_TIMEOUT_MS`/`MAX_TURN_TIMEOUT_MS` validation in `applyMove` (Phase 02-18) still constrains every value the control can emit |
| T-03-12 | Spoofing | player-name truncation | accept | Adding `min-w-0` makes a long player name truncate visually rather than overflow. A truncated name could in principle look like another player's, but names are already free-text and already truncated on the game screen's player tiles; this phase does not make the situation worse and name uniqueness was never a security property of this app |
| T-03-SC | Tampering | npm installs | accept | No packages installed; 03-RESEARCH.md records zero new dependencies for the phase |
