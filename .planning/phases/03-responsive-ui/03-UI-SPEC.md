# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is a retrofit onto already-shipped, hand-built components (`Card.tsx`, `Hand.tsx`, `Table.tsx`, `GameScreen.tsx`, `LobbyScreen.tsx`) — no new game mechanics, no visual/animation redesign beyond what RESP-01..05 require (that's Phase 6/POLISH-03's job, per `03-CONTEXT.md`'s phase boundary). Every value below is either **(a)** the existing, already-shipped value this phase must preserve, or **(b)** a new value this phase specifically introduces for keyboard focus, touch sizing, or reflow. Each row is labelled accordingly.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind components, no headless/primitive library (Radix, Base UI, shadcn) anywhere in the codebase |
| Icon library | lucide-react ^0.562.0 (already installed; used via `HelpCircle`, `X`, `Copy`, `Check`, `Crown`, `Link2`, `WifiOff`, `UserX`, `LogOut`) |
| Font | System default — Tailwind's stock `font-sans` stack. No custom `@font-face`/webfont is loaded anywhere in `index.css`/`index.html`. |

**shadcn gate — declined, not deferred.** No `components.json` exists and the stack is Vite/React, so the gate in `gsd-ui-researcher.md` triggers, but this phase's entire component inventory (`Card.tsx`'s six-colour deck-back gradients, `Hand.tsx`'s roving-tabindex listbox, the celebration modal) is bespoke card-game visual design that a generic shadcn preset (dialogs, selects, form primitives) would not replace — RESEARCH.md's own Standard Stack section independently reached the same conclusion ("no new runtime dependencies are required or recommended... a dialog library now would create migration friction against Phase 6's stated plan"). Initializing shadcn now would add an unused dependency and a preset decision with no consumer in this phase. Reversible: nothing here blocks introducing shadcn in a later phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- **44px (2.75rem) touch-target minimum** — every interactive control audited under RESP-03 (sort buttons, Leave Game/Dismiss/Copy-code/Copy-link/Remove-player buttons, the auto-pickup `<select>`) must resolve to at least `min-h-11 min-w-11` (Tailwind's `11` = 2.75rem = 44px, [VERIFIED in 03-RESEARCH.md] against `tailwindcss/defaultTheme`). This is WCAG 2.5.5's *Enhanced* figure, deliberately the stricter of the two WCAG 2.2 target-size criteria — see 03-RESEARCH.md's State of the Art table.
- **Same-rank hand-card overlap (`Hand.tsx`'s `-mr-12`, existing) is removed entirely below the `sm` breakpoint** (D-11): `max-sm:mr-2` replaces `-mr-12` on grouped cards under 640px, so every card in the horizontally-scrollable phone strip (D-09) is fully un-occluded and hits the full `w-20` (80px) tappable width. Full removal, not a reduced overlap value — the phone layout already gets scroll room from D-09's strip, so there is no desktop-style fitting pressure that the overlap exists to solve, and full removal is the safer, more prescriptive choice per Pitfall 5 in 03-RESEARCH.md.

## Typography

This phase governs the **Body** and **Label** rows below — text it creates or directly touches for RESP-02/03/04/05 (sort buttons, keyboard-focus/aria-label text, the new turn announcer). **Heading** and **Display** rows document pre-existing values this phase must leave unchanged, per `03-CONTEXT.md`'s explicit phase boundary excluding visual/animation polish (Phase 6/POLISH-03 scope). Only 2 weights (400/600) govern the Body/Label rows this phase actually modifies; Heading/Display's pre-existing 700/900 weights are out of this phase's contract, not a violation to fix.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 (regular) | 1.5 |
| Label | 14px (`text-sm`) | 600 (semibold) — grown from the existing 500 (`font-medium`) tooltip weight for consistency across everything this phase touches (sort buttons, card tooltip/aria-label text, turn announcer) | 1.2 |
| Heading *(pre-existing, unchanged)* | 20px (`text-xl`) | 700 (bold) | 1.2 |
| Display *(pre-existing, unchanged)* | 36–72px (`text-4xl`–`text-7xl`) | 900 (black) | 1.1 |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slate-900` → `purple-900` gradient (`bg-gradient-to-br from-slate-900 via-purple-900 to-slate-900`) | Page background — existing, unchanged by this phase |
| Secondary (30%) | `slate-800` (`bg-slate-800`) | Panels, cards, dialogs, LobbyScreen player rows — existing, unchanged |
| Accent (10%) | `pink-500` → `purple-500`/`purple-600` gradient | Primary CTA buttons ("Ready to Play", "Start Game"), the active sort-mode button state, the app logo/heading gradient text — existing, unchanged; the sort buttons keep this accent for their active state while growing in size per D-13 |
| Destructive | `red-600` / `red-500`→`pink-500` gradient | "Pick Up Pile" button, the Leave Game confirmation's "Leave Game" button, the shithead/loser celebration modal's border — existing, unchanged |

Accent reserved for: primary CTA buttons ("Ready to Play", "Start Game"/join actions in `MenuScreen`), the active sort-mode button (`Hand.tsx`), and the app wordmark/heading gradient text. Never applied to the new focus ring below.

**New interaction-state color this phase introduces:** `cyan-400` (`ring-cyan-400`), used **exclusively** for the `focus-visible` keyboard-focus ring on cards and interactive controls (D-04). This is a state indicator, not a surface color, and sits outside the 60/30/10 split — it must stay visually distinct from the existing selected-state `ring-yellow-400` ring and the existing hover `scale-110 -translate-y-2` lift, so focused/selected/hovered remain individually legible to a sighted keyboard user. Recommended composition (from 03-RESEARCH.md's Code Examples):

```
focus-visible:outline-none focus-visible:ring-4 focus-visible:ring-cyan-400 focus-visible:ring-offset-2 focus-visible:ring-offset-slate-900
```

`focus-visible:` (not bare `focus:`) so the ring only appears for keyboard/AT focus, never for a mouse click that also focuses the element.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new CTA copy is authored this phase. The existing "Play {N} Card{s}" / "Pick Up Pile ({N})" / "Ready to Play" buttons (already real `<button>` elements in `GameScreen.tsx`) become keyboard-reachable via the hand/table listbox's Tab order (D-02); copy text is unchanged. |
| Empty state heading | Not applicable — this phase introduces no new empty-data view (no list this phase adds can be empty). Default: no empty-state copy required. |
| Empty state body | Not applicable, as above. |
| Error state | Not applicable — this phase adds no new error-producing flow; existing toast error copy (Phase 1/2 scope) is untouched. |
| Destructive confirmation | Leave Game (existing, unchanged): heading "Leave game?", body "You can rejoin any time with the same room code - your seat will be waiting.", buttons "Keep Playing" / "Leave Game". In scope for this phase's RESP-03 touch-target audit only (`px-4 py-2` buttons are ~40px tall today — grow to `min-h-11`); copy itself is unchanged. |
| Turn announcement *(new — RESP-05/D-05)* | `sr-only`, `aria-live="polite"` text: **"Your turn"** when `gameState.currentTurn` is the local player, **"{PlayerName}'s turn"** otherwise. Announced only on a genuine `currentTurn` index change, never re-announced on unrelated re-renders (03-RESEARCH.md Pattern 3 / Pitfall 3). No board-state summary — deliberately kept short so it doesn't compete with move-result toasts. |
| Face-down card accessible name *(new — Pitfall 4 fix)* | Fixed, non-identifying `aria-label="Face-down card"` on every face-down `Card` instance (hand setup, table face-down pile, draw pile), identical string regardless of the card's actual rank/suit. Preserves the blind-play invariant (D-08 / CLAUDE.md's documented testing gotcha) — this label must never vary with the card's real identity. |
| Face-up card accessible description *(new — Pitfall 4 fix)* | Reuse the existing tooltip `title` string verbatim as the `aria-label`/`aria-describedby` text (e.g. "Not your turn", "First turn: only {rank}s allowed", "Play from face-up or face-down first", plus `getCardPlayability`'s dynamic tooltip). No new copy authored — the same string sighted mouse users already see on hover becomes available to keyboard/AT users on focus. |
| Celebration dialog accessible name *(new — RESP-05/D-06)* | `aria-labelledby` pointing at the modal's existing visible heading text ("SH!THEAD!" / "SAFE!", give it an `id`) rather than a new `aria-label` string — avoids maintaining two copies of the same string; resolves 03-RESEARCH.md's Open Question 2 in favour of `aria-labelledby`. |
