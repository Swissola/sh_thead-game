## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Elevation of Privilege | `Hand.tsx` keyboard selection | mitigate | Keyboard selection reuses the untouched `onClick` branch, which already gates on `isSetupPhase`, `isMyTurn`, `getAvailableCardSource(player) === 'hand'` and `canAddToSelection`. No new `setSelectedCards` call site is added (asserted by an acceptance criterion), so no keyboard path can build a selection the mouse path would have rejected. `applyMove` and the server-side `apply-move` Edge Function remain the authority regardless |
| T-03-08 | Tampering | roving-tabindex option count | mitigate | The `isDrawing` placeholder branch is deliberately excluded from `role="option"`, keeping the hook's DOM query result in step with `handCardCount`; a mismatch would let the cursor address a non-existent card and leave the listbox untabbable (Pitfall 1) |
| T-03-01 | Information Disclosure | `Hand.tsx` `aria-label` | mitigate | The hand contains only face-up cards the player already sees; `ariaLabel` is fed the existing `tooltip` string, which is composed from fixed literals and the player's own card ranks. No face-down card is rendered by this component, so the blind-play invariant is not reachable here |
| T-03-SC | Tampering | npm installs | accept | No packages installed; 03-RESEARCH.md records zero new dependencies for the phase |
