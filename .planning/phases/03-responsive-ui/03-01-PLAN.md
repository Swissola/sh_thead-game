    Create `src/hooks/useRovingTabindex.ts` exporting a single named function `useRovingTabindex(itemCount: number)` (no default export, matching `useHandSorting.ts`).

    Return shape — an object with exactly these four members:
    - `containerRef: React.RefObject<HTMLDivElement | null>` — created with `useRef<HTMLDivElement | null>(null)`, attached by the caller to the listbox container element.
    - `activeIndex: number` — the clamped cursor position; `-1` when `itemCount` is 0.
    - `getItemProps(index: number): { tabIndex: number; onFocus: () => void }` — returns `tabIndex: index === activeIndex ? 0 : -1` and an `onFocus` that sets the raw cursor to `index` (keeps mouse-driven focus in sync with the cursor).
    - `onKeyDown: React.KeyboardEventHandler<HTMLDivElement>` — the container-level arrow/Home/End handler.

    Internal state is a single `useState<number>(0)` holding the raw cursor. `activeIndex` is **derived on every render**, not stored: `itemCount === 0 ? -1 : Math.min(Math.max(rawIndex, 0), itemCount - 1)`. This derivation is the Pitfall 1 clamp — do NOT implement it as a `useEffect` that calls `setState`, because this project's lint config rejects effect-body `setState` (see STATE.md's Phase 02-12 decision).

    `onKeyDown` maps `ArrowRight`/`ArrowDown` to `activeIndex + 1`, `ArrowLeft`/`ArrowUp` to `activeIndex - 1`, `Home` to `0`, `End` to `itemCount - 1`. For any of those five keys: call `event.preventDefault()`, clamp the target into `[0, itemCount - 1]`, store it via the state setter, and move real DOM focus by reading `containerRef.current.querySelectorAll<HTMLElement>('[role="option"]')` and calling `.focus()` on the element at the clamped index. Return early without `preventDefault` for every other key, so Enter/Space keep bubbling to the card's own handler and Tab still leaves the listbox.

    Do not import anything from `gameLogic.ts`, `types.ts`, or any component — this hook is generic over "a container with `[role="option"]` descendants" and must stay reusable by both `Hand.tsx` and `Table.tsx`.

    Create `src/__tests__/hooks/useRovingTabindex.test.tsx` (`.tsx`, not `.ts` — it renders a harness component). The harness renders a `div` with the hook's `containerRef`/`onKeyDown` attached and `itemCount` children, each a `button` (or `div`) with `role="option"` and the hook's `getItemProps(i)` spread onto it. Drive it with `fireEvent.keyDown(container, { key: ... })` and assert `document.activeElement`, exactly matching the repo's existing `fireEvent`-based style (`@testing-library/user-event` is not installed).

    Implementation follows 03-RESEARCH.md's Pattern 2 code example. Concrete requirements:
    - Two refs: `containerRef` for the dialog element, `previouslyFocused` holding `HTMLElement | null`.
    - One `useEffect` with dependency array `[active, onEscape]` that returns early when `active` is false.
    - On activation, record `document.activeElement as HTMLElement | null` into `previouslyFocused`, then focus the first match of the focusable selector `a[href], button:not([disabled]), textarea, input, select, [tabindex]:not([tabindex="-1"])` within the container.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DOM ↔ assistive technology | Attributes and text this phase adds become the accessibility tree — anything exposed there is readable by a screen reader even when invisible on screen |
| keyboard input → game state | New key handlers become a second input path alongside mouse click; both must funnel into the same validated move pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Tampering | `useFocusTrap` Tab handling | mitigate | Tab/Shift+Tab wrap is enforced with explicit `preventDefault()` plus a manual `.focus()` call at both ends; test 2 and test 3 in Task 2 assert containment rather than trusting native tab order |
| T-03-04 | Elevation of Privilege | `useRovingTabindex` key handling | mitigate | The hook moves focus only — it never dispatches, mutates selection, or touches `GameContext`. Enter/Space are deliberately left unhandled so they reach the card's existing click handler, keeping `dispatchMove` → `applyMove` (and the server-side `apply-move` Edge Function) the only path to state change |
| T-03-06 | Denial of Service | `useFocusTrap` document listener | mitigate | The `keydown` listener is removed in effect cleanup; test 6 asserts no listener is active when `active` is false, so a closed modal cannot swallow the page's keyboard input |
| T-03-SC | Tampering | npm installs | accept | This phase installs no packages. 03-RESEARCH.md's Package Legitimacy Audit records zero new dependencies; if any task in this plan reaches for `npm install`, stop and re-plan rather than proceeding |
